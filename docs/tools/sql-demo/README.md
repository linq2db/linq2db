# Landing Page SQL Demo — Maintenance Guide

The landing page at `docs/source/index.md` features a tabbed demo showing C# LINQ code alongside the SQL linq2db generates for it, with a switcher for the SQL dialect (SQL Server, PostgreSQL, MySQL, Oracle, SQLite). The SQL panes are generated by `SqlDemoGenerator.cs`, which also checks that the page still shows what the current linq2db generates.

## Architecture

- **C# side**: Hand-written syntax-highlighted HTML using `<span>` classes (`code-keyword`, `code-type`, `code-string`, `code-number`, `code-comment`).
- **SQL side**: Written by `SqlDemoGenerator.UpdateLandingPage` between `<!-- sql-demo:<tab> -->` and `<!-- /sql-demo:<tab> -->`: one `demo-sql-variant` block per dialect, holding the SQL linq2db generates for the tab — `ToSqlQuery()` for a query, the commands it sends for an executing call such as Upsert — laid out for the pane and highlighted with the same span classes. A dialect the tab names as unsupported (MERGE on MySQL and SQLite) gets a note instead, and the generator checks that the dialect still refuses it. Do not edit these regions by hand.
- **Temp Table**: The exception. It shows the statements that `CreateTempTable` and the join really execute on SQLite in memory (CREATE, the bulk copy INSERT, the SELECT, the DROP from `Dispose`), formatted by hand with numbered `--` comments and the 500-row `VALUES` list abbreviated. It has no dialect switcher and no check; `main.css` hides the switcher for it with two `#demo-tab-8` rules.
- **Tabs and dialects**: Pure CSS — two `role="radiogroup"` bars of visually hidden but focusable `<input type="radio">` elements, each right before its `<label>`. `main.css` shows the panel and the dialect block whose radio is checked with `.demo-container:has(#… :checked)` rules (no JavaScript). Keyboard users switch with the arrow keys.
- **Width**: The generator keeps lines within `SqlHtml.MaxWidth` (56) where it finds a break point; the widest SQL line today is 58 characters, the widest C# line 47. `main.css` is sized for that: the panes split the demo 47:58, and the demo sits beside the text from 1220px and under it below that. A wider line scrolls sideways, so break it or adjust the split and that breakpoint.

## How to update the SQL panes

`SqlDemoGenerator.cs` holds one method per tab, with the same C# as the tab, and renders it for every dialect offline: a query through `ToSqlQuery`, which never opens a connection, and an executing call through `CaptureConnection`, which records the commands instead of running them. Two tabs were also compared with live databases, using the generator's dialect options: the Upsert tab's SQL equalled what the call sends to SQL Server 2022, PostgreSQL 16, MySQL 8, Oracle 23 and SQLite, and the Merge tab's what `.Merge()` sends to SQL Server 2022. The other tabs show `ToSqlQuery`'s output and were not run on a server. The generator is a reference copy and is not compiled where it lives.

### 1. Copy the generator into the playground

From the repository root:

```bash
cp docs/tools/sql-demo/SqlDemoGenerator.cs Tests/Tests.Playground/SqlDemoGenerator.cs
```

**Never commit the copy** — `Tests/Tests.Playground` takes no new source files in a PR.

### 2. Edit the tab methods if a tab changes

Keep each method's C# identical to its tab's C# pane, except:

- Merge stops before the executing `.Merge()`.
- Temp Table first creates `Products` (`CreateTable<Product>()`, not traced), wraps the temp table in a `using (…) { }` block where the pane has `using var tmp`, and ends the join with `ToList()` so it runs; the pane's C# shows the query without enumerating it.

### 3. Regenerate the panes

```bash
dotnet test --project Tests/Tests.Playground/Tests.Playground.csproj -c Testing -f net11.0 \
  --filter "FullyQualifiedName~SqlDemoGenerator.UpdateLandingPage" --output detailed --test-progress
```

`UpdateLandingPage` is `[Explicit]`: it runs only when named. It rewrites the marked regions of `docs/source/index.md` and prints a warning for every line wider than `SqlHtml.MaxWidth`. Review the result with `git diff`.

### 4. Check the page

```bash
dotnet test --project Tests/Tests.Playground/Tests.Playground.csproj -c Testing -f net11.0 \
  --filter "FullyQualifiedName~SqlDemoGenerator" --output detailed --test-progress
```

`LandingPageIsCurrent` fails while any region differs from what the current linq2db generates, on a region no tab owns, on a `sql-demo` marker outside a well-formed region and on two regions with one id; run it after a linq2db change that may alter the SQL. Marker problems are fixed by hand: `UpdateLandingPage` refuses such a page. `TempTable` prints the executed SQLite statements for the hand-formatted Temp Table pane.

### 5. Copy the generator back and delete the playground copy

```bash
cp Tests/Tests.Playground/SqlDemoGenerator.cs docs/tools/sql-demo/SqlDemoGenerator.cs
rm Tests/Tests.Playground/SqlDemoGenerator.cs
```

## Adding a new tab

1. Add `<input type="radio" name="demo-tab" id="demo-tab-N" class="demo-radio" /><label for="demo-tab-N" class="demo-tab">…</label>` to `.demo-tabs`.
2. Add a `.demo-panel-N` div to `.demo-panels`: the C# pane, an SQL pane holding an empty `<!-- sql-demo:<id> -->` / `<!-- /sql-demo:<id> -->` region (`<id>`: lowercase letters and hyphens), and a `demo-more` link to the matching article. A link written as `href="xref:<uid>"` is checked by the build but comes out with class `xref`; `main.css` styles `.demo-panel > a.xref` the same way.
3. Add `.demo-container:has(#demo-tab-N:checked) .demo-panel-N` to the visibility rule in `docs/source/templates/custom/public/main.css`. If the new tab goes before Temp Table, renumber the tabs after it and move the two Temp Table rules (`#demo-tab-8` today) with it.
4. Add the tab's method and a `Tab` entry with the same `<id>` to `SqlDemoGenerator.cs` (`Sql` for a query, `Execute` for a call that runs), then run `UpdateLandingPage`. A dialect that cannot run the tab is named in `UnsupportedOn`, with the note text in `Unsupported` and a phrase of the refusal's message in `UnsupportedReason`; the three go together and neither text may be blank, and the generator fails if a named dialect runs the tab after all.

Adding a dialect is the same: a radio and label in `.demo-dialects`, a `Dialect` entry in the generator, and a `.demo-container:has(#demo-dialect-<id>:checked) .demo-sql-variant[data-dialect="<id>"]` line in `main.css`.

## Syntax highlighting classes

| Class | Color | Used for |
|-------|-------|----------|
| `code-keyword` | Purple (#c792ea) | C# keywords, SQL keywords (SELECT, FROM, WHERE, etc.) |
| `code-type` | Blue (#82aaff) | Type names (Product, DataConnection), SQL functions (COUNT, SUM) |
| `code-string` | Green (#c3e88d) | String literals |
| `code-number` | Orange (#f78c6c) | Numeric literals |
| `code-comment` | Gray (#8b93bd) | Comments (// and --) |

## Important: blank lines in `<pre>` blocks

DocFX's Markdown processor converts blank lines inside `<pre>` into `<p>` tags. Use `&#10;` (newline entity) instead of actual blank lines to create visual spacing inside `<pre>` blocks; the generator does this for the SQL panes.
